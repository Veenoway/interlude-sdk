# __APP_NAME__

A contract on Monad that answers in a millisecond, with no gas and no wallet prompt after the
first signature.

`contracts/Clicker.sol` is an ordinary Solidity contract that inherits Interlude's
`Delegatable`. Once delegated, an Interlude node holds its state and runs its calls; every few
seconds the node commits the storage diffs back to the same contract on Monad under a validator's
signature and bond, where anyone can challenge them. `web/` is a Next.js page that opens a
session with one signature and then clicks through the node.

## From zero to a live delegated app

You need Node 20.9 or later, [Foundry](https://getfoundry.sh) (`forge` on your PATH) and a
browser wallet (MetaMask, Rabby, Phantom). Clicking needs no MON. Taking ownership of the app
(step 3) is one transaction on Monad testnet, so that address needs a little testnet MON.

```sh
cd contracts
npm i
npm run build
npx interlude ship --owner <your address> --out ../web/.env.local
cd ../web && npm i && npm run dev
```

Then open http://localhost:3000, connect, open a session, click.

The project asks for `@interludelayer-sdk/cli` and `@interludelayer-sdk/sdk` `^0.2.1`: the
releases that bundle the v3 hub and name the v3 public floors. Do not settle for an older one
if npm offers it: CLI 0.1.x silently ignores `--owner` and `--out`, so the app would stay owned
by Interlude's deploy key.

1. **`npm i`** installs `@interludelayer-sdk/cli`, which carries Interlude's Solidity sources.
2. **`npm run build`** (`interlude check`) copies those sources into `lib/interlude`, compiles,
   and proves that `src/ClickerInterludeSurface.sol` still matches the storage layout solc
   produced. After this, plain `forge build` and `forge test` work too. `npm test` runs both.
3. **`interlude ship`** sends the bytecode and `interlude.toml` to Interlude's control plane,
   which deploys Clicker on Monad testnet, calls `delegateAll()`, starts a node for it and
   prints the app address and the node URL. `--out` writes them into `web/.env.local` as
   `NEXT_PUBLIC_INTERLUDE_APP`, `NEXT_PUBLIC_INTERLUDE_NODE` and
   `NEXT_PUBLIC_INTERLUDE_BASE_RPC`. `--owner` hands the contract to you: `ship` prints the
   `cast send <app> "acceptOwnership()" ...` to run once from that address. A 502 from the node
   URL during the first few minutes is its machine starting.
4. **`npm run dev`** in `web/` serves the page. Next.js reads `.env.local` at start-up, so
   restart it after shipping again.

`npx interlude status <app>` shows the owner, the pending owner, the delegation and the node's
health at any time.

## What is where

```
contracts/
  src/Clicker.sol                    the app: every Interlude-specific line is commented
  src/ClickerInterludeSurface.sol    generated by `npm run gen`; do not edit
  test/Clicker.t.sol                 forge tests: guard, surface, commits, session keys
  interlude.toml                     what ship and dev deploy, and how
web/
  lib/interlude.ts                   the SDK client and hooks, bound to Clicker's ABI
  lib/abi.ts                         generated by `npm run abi` (typed `as const`)
  lib/wallet.ts                      injected wallet, moved to the base chain before signing
  components/clicker-app.tsx         connect, open a session, click, watch it settle
```

## Changing the contract

1. Edit `contracts/src/Clicker.sol`. Put new state **below** the existing variables and
   annotate it `/// @custom:interlude global` if the node should hold it.
2. `npm run gen` rewrites the surface from the new layout, and `npm run build` checks it.
   Keep `npm run check` in CI: it fails when the layout and the surface disagree.
3. `npm run abi` rewrites `web/lib/abi.ts`, so the page's calls are typed against the new ABI.
4. Add the new function names to `SCOPE` in `web/lib/interlude.ts` if a session key should be
   able to call them.
5. `npx interlude ship --owner <you> --out ../web/.env.local` deploys a new copy at a new
   address. Shipping the exact same build twice is refused with the existing address;
   `--again` deploys a second copy on purpose.

`npm run dev` in `contracts/` (`interlude dev`) runs the whole stack on your laptop: anvil, a
hub, a bonded validator, Clicker, the delegation and a node, and writes `web/.env.local` for
it. It needs an `interlude-node` binary, and that binary is in neither the npm packages nor the
[`interlude-sdk` repository](https://github.com/Veenoway/interlude-sdk), which carries the SDK,
the CLI and this template. It is built from the Interlude monorepo
(`cargo build --release -p interlude-node`, then `INTERLUDE_NODE_BIN` pointed at it), so the
local loop is for people with that checkout. You do not need it to ship, and you do not need
anything to try the SDK first: the public floors are live Rooms with their nodes
([demo.interludelayer.xyz/room](https://demo.interludelayer.xyz/room) in a browser;
`PUBLIC_DEMO_FLOORS`, `roomAbi` and the SDK's `examples/try.mjs` from code).

## What you are trusting

This is Interlude v1, and it is permissioned. Be clear about what that means before you put
anything of value in it.

- **Interlude deploys your contract.** `ship` sends bytecode, not a transaction: the control
  plane deploys from its own key, because `delegateAll()` is owner-only and has to be called by
  whoever deploys. **Without `--owner`, Interlude's key stays the owner**, with everything that
  lets it do (`undelegate`, a new delegation). With `--owner`, ownership is offered to your
  address once the delegation is open, and it is yours when you call `acceptOwnership()`. Until
  then, Interlude's key still is the owner. To deploy with your own key instead, deploy and call
  `delegateAll()` yourself, then `npx interlude sessions create <app>` asks for a node.
- **Interlude runs the validator and the node.** They see and order every call. A commit that
  misstates what the node executed can be challenged on Monad during the validator's challenge
  window; a proven fraud slashes its bond and rewinds the diffs. Validators and resolvers are
  allowlisted in v1: that is the trust you are extending.
- **The state is the node's while delegated.** `whenNotDelegated` refuses writes on Monad until
  the delegation ends. Ending it is not instant either: the validator's bond stays held for the
  challenge window after `undelegate`, so a fraud found late can still be proven, and anyone
  can call `hub.releaseStake(app, partition)` once the window has passed.
- **Session keys** live in the tab's `sessionStorage`, can call only the functions in the
  grant's scope (`click` here), carry no value (`withSession` is not payable), and expire after
  an hour. Any script on the page can use the key until then. `hub.bumpSessionEpoch()` revokes
  every grant a user ever signed, but a node that is already running reads the epoch at the
  block it pinned when the delegation opened, so it only sees a revocation when the delegation
  is renewed. Expiry is what bounds a live session.

## Limits worth knowing first

- **Global partition only when hosted.** The hosted node serves the whole contract as one
  partition (`GLOBAL`). `per-key` storage (one partition per room or per user) works with
  `interlude dev` only, and `ship` refuses it.
- **Mapping keys must be computed at runtime.** The node learns which entry a hashed slot
  belongs to by watching the EVM hash the key. With a `constant` key the optimizer folds the
  hash into a literal, the node never sees it happen, and it has to refuse the write. Use
  `immutable` for a fixed key (`clicks[_actor()]` is already fine).
- **Every writer needs the guard, inherited ones included.** Plain storage cannot guard itself,
  so `whenNotDelegated(Types.GLOBAL)` goes on every function that writes delegated state. An
  inherited writer (an OpenZeppelin `transfer`, `_mint` reachable from a public function) has
  no guard: override it and add one, or keep that state out of the delegated surface.
- **Session calls run with `msg.sender == address(this)`.** `withSession` reaches your function
  through a self-call, so use `_actor()` for "who is calling" in anything a session can reach.
  Anything that trusts `msg.sender` (an inherited `onlyOwner`, an ERC-20 `transfer` from the
  app's own balance) acts with the contract's own authority there. Keep such functions out of
  every session scope; `Delegatable` already refuses the delegation controls.
- **Constructor arguments and seeding are explicit.** Clicker takes only the hub, which `ship`
  fills in. Any other constructor argument goes in `args` in `interlude.toml`, one string per
  input; nothing guesses them. State to seed before the delegation opens goes in `[[setup]]`.
- **Solidity 0.8.28 or later, EVM Cancun or later.** Interlude's contracts use transient
  storage. `foundry.toml` pins both; lowering either breaks the build inside `lib/interlude`.
- **Ship is rate limited** per IP. A room of people behind one IP shares that budget.
